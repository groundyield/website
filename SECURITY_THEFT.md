# Crime, theft, and asset control

**How GroundYield reduces theft and vandalism risk on modular units and school kits**  
Last updated: 27 July 2026  
**Status:** Design controls v0 — to be stress-tested in Rumbacaca / Vilanculos  

Related: [WHY_OTHERS_FAILED.md](WHY_OTHERS_FAILED.md) · [RISK_AND_GAPS.md](RISK_AND_GAPS.md) · [VALUE_AND_MONEY.md](VALUE_AND_MONEY.md) · [UNIT.md](UNIT.md) · [SAFETY.md](SAFETY.md) · [UNIT_AGREEMENT_DRAFT.md](UNIT_AGREEMENT_DRAFT.md)

## 1. Why this is a first-class risk

Across Mozambique and the wider region, **solar panels and water pumps are high-value, easy to resell, and frequently stolen or vandalised** when:

- Kits are installed as **anonymous project gifts** with no local owner  
- Many units drop with **little training**  
- Equipment is **fixed in the open** far from houses  
- Community feels **no stake** in the asset  
- Night security is weak and formal police response is slow  

If a ~$1–2k irrigation kit vanishes, the pilot fails **and** the household is left with a hole and a story that “projects bring thieves.”

**We treat theft as a design problem**, not only a police problem.

---

## 2. Principles

1. **Stake before steel** — no kit until a named household/group accepts written care rules.  
2. **Earn > steal** — package must create visible ongoing value (water, crop) so neighbours defend it.  
3. **Moveable when needed** — prefer components that can be taken home at night or locked.  
4. **Small surface area** — few units, not 50 pumps in year one.  
5. **Public inventory** — serials, photos, unit_id; theft becomes a dated public failure, not a hidden shame.  
6. **No cash on plots** — reduce robbery of people, not only of panels.  
7. **Community justice first** — local leaders before external force escalation.

## 3. Controls by asset type

### A. Solar panels

| Control | How |
|---------|-----|
| **Location** | Near dwelling / compound when possible — not isolated bush alone |
| **Mounting** | Secure frames; anti-lift bolts where practical |
| **Removable panels** | Night storage indoors when theft risk extreme (trade-off: labour) |
| **Marking** | Engrave / indelible mark + photo + serial in unit file |
| **Shared watch** | Neighbour agreement in annex — theft hurts the group |
| **Insurance** | Only if available and costed; never assume |

### B. Pumps and controllers

| Control | How |
|---------|-----|
| **Portable pumps** | Prefer models that can be **removed daily** in high-theft zones (regionally, theft fear has driven portable solar pump designs) |
| **Controller indoors** | Electronics not left in field |
| **Hose/pipe** | Bury or hide where practical; cheap pipe is still friction for thieves |
| **Spare parts** | Don’t stock resale-attractive inventory on-site |

### C. Starlink / school kits (if any)

| Control | How |
|---------|-----|
| School compound | Higher foot traffic than isolated plot |
| Locked room for router | Staff custodian named |
| Mount dish where visible | Theft in open may be riskier for thief |
| Community hours written | Reduces “outsider toy” perception |
| Separate from farm kit | Don’t park all assets in one undefended spot |

### D. Harvest and cash

| Control | How |
|---------|-----|
| Hermetic bags in house | Not stacked unattended at plot edge |
| Sell in daylight | Avoid night cash walks |
| No public “we paid them lots of money” theatre | Reduces targeting |

## 4. Social controls (often stronger than locks)

| Control | Why it works |
|---------|----------------|
| **Local selection of who gets a unit** | Fairness cuts sabotage |
| **Association / elders witness annex** | Social enforcement |
| **Open costs** | Less rumour of “rich project” cash piles |
| **Jacques known in Rumbacaca** | Relationship capital — still re-earn, don’t assume |
| **Benefit visible to neighbours** | Water shared rules if any; or clear household-only with community OK |
| **Fast response to first incident** | Ignore first theft → cascade |

**Sabotage** (jealousy, land disputes) is different from random theft — baseline + legitimacy first.

---

## 5. Contract / annex clauses (must write)

For every unit, the annex should state:

1. Who is **custodian** of panels/pump (name + role)  
2. Night storage rules (if any)  
3. What happens if kit is **stolen** (report, local process, whether replacement exists — usually **no automatic free replace**)  
4. What happens if **neglect** (not theft) destroys kit  
5. Right to **move kit** to another household if care fails (with association witness)  
6. No sale of project kit without written OK  

See models A–D in [VALUE_AND_MONEY.md](VALUE_AND_MONEY.md).

---

## 6. Incident response

| Step | Action |
|------|--------|
| 1 | Safety first — no heroics |
| 2 | Document: date, what missing, serials, photos of scene |
| 3 | Inform household + local leader same day |
| 4 | Police report only if safe and useful (local advice) |
| 5 | Public log: unit_id, loss type, value band — **no** naming suspects in public git |
| 6 | Design change: update this file if a new mode appears |
| 7 | Replacement: only if budget + new security plan — not automatic |

---

## 7. What we will not do

| Don’t | Why |
|-------|-----|
| Arm guards as default brand | Escalation / wrong for community pilot |
| Hide theft to protect image | Integrity failure |
| Install 20 solar kits before one survives a season | History of mass-fail projects |
| Blame “the community” as a whole for one thief | Destroys G1 trust |
| Leave kit when operator exits permanently without handover | Creates abandoned loot |

---

## 8. Fit with “many tried before”

Failed waves often combined **high-value kit + low local stake + weak training**.  
Our counter is **few units, high stake, moveable kit, social annex, public inventory**.

Still: **no guarantee**. Crime is real. We only claim controls, not perfection.
